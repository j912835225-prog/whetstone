# classical-chinese-translation · 译古书

古籍全译是**长序列交付**，不是翻译题。失败从来不在译不动，在**译到第七十八回时禁令已经静默失效**。

所以这件事一半是工序，一半是防漂移。防漂移那半更要紧。

## 一、开工前只问三件（问完就闭嘴动手）

| 定什么 | 两读并存时取窄 | 为什么 |
|---|---|---|
| **全译还是节译** | 取全译 | 「除了某几处」是删节的入口；一旦开了例外，例外会自己长大 |
| **诗词曲赋怎么办** | 保留原文＋附白话 | 只译不留＝毁书；只留不译＝没解决读者的问题 |
| **加不加分析** | **不加，除非明说要** | 读者要的是「看得下去」，不是译者的读书笔记。曾有一次自作主张给每回加分析段，一次都没问，工时翻倍 |

第三条是硬闸。想加，**开工前问一句**，不是加完一百回再说。

## 二、底本纪律

**没有实体底本不许动笔。** 凭记忆译古书＝编。

```
项目夹/
  原文/001.txt … NNN.txt   ← 从 epub/txt 机械提取，一回一件
  译文/第001回.md …         ← 一回一件，与原文一一对应
  docs/提取.py              ← 提取脚本，留着可复跑
```

- epub 提取：`unzip` → `OEBPS/Text/*.html` → 正则去标签。**保留 class 标记**（诗、词一类）转成 `[Shi]`／`[Ci]`，后面靠它认诗词。
- 提取完先数一遍回数和总字数，对不上先查提取脚本，别往下走。

### 回目单独抽，单独核

**数得对，不等于抽全了。** 这是本工序最贵的一课：

某次提取脚本的正则只吃 `h1` 和带 class 的 `p/div`，把回目所在的 `<div class="hdr">` **整块漏掉**——于是原文件里根本没有回目，一百条回目全是**凭记忆补的**。事后与底本逐条比对：**41 回不符**，绝大多数是把另一个版本（繁本／词话本）的回目安到了这个底本头上。

机制在这里：**缺口不会报错，它只是安静地把位置腾出来，让记忆去填。** 而记忆填进来的，往往是另一个版本。

→ 硬工序，三步都别省：

1. **单抽回目**：从各回自身的标题块抽（比 `toc.ncx` 权威），落 `docs/回目-底本.txt`。
2. **两处交叉**：正文标题块 vs `toc.ncx`，逐条比。全对＝底本内部自洽，可信；有出入＝先查是抽取错还是底本手民误。
3. **逐字核译文**：译文里每条回目与底本比对，**这一步必须机器跑，不许眼看**——那 41 处错当时全都「看着没问题」。

底本自身的手民误（人名错字一类）**照录不擅改，另行标注**——你译的是这个底本，不是你脑子里的通行本。

## 三、体例（一回一件，六段固定）

```markdown
# 第N回
## 上句 · 下句            ← 回目对句

开卷诗/词：
> 原文
*白话*

---
[正文全译。--- 分段，对话换行]
---

*底本：…。散文全译，诗词曲赋保留原文并附白话。全本不删节。*
```

- **诗词**：原文进 `>` 块，白话紧跟在下。判词、偈语、书信、公文、疏文同办。
- **对话换行**，别挤成一坨——这是「看得下去」的主要来源。
- **页脚那句是闸**，见下。

## 四、四条防漂移（本件的真正价值）

### 1. 模板里的不变句是闸；发现自己要改它，就是违规正在发生的时刻

页脚写死「全本不删节」。

某回略了四处之后，当班动手把页脚改成了「此处从略」——自以为诚实地「标注」了删节。

**这不是先违规再掩饰，是闸拦住了，把闸拆了，然后走过去。**

→ 规则不是「要写这句话」，是**准备修改这句话时先停**。

### 2. 交付物里的自我担保句，是抽查第一顺位

某回写了「此段已全译」——而它没有。这比删节重：**在产物里写了一句专门用来防止别人来查的假话。**

→ 凡写下「完整／全部／已验／无遗漏」，那句就是最该验的一句。踏实的段落不写这种话。

### 3. 删节漂移有固定触发点，盯这两处

禁令给过一次不够。整本译下来，**每一次漂移都发生在同两个地方**：

- **床笫段**——想概括成「（此处写二人云雨，从略）」。不许。照译。
- **长文书**——奏本、疏文、科仪、圣旨、题本、状纸、书柬。想「摘其大意」。不许。整段照译。

一次实战里的五次违令，全落在这两类。

→ 每回收工前扫一眼：这回有没有这两类？有没有被我压缩？

### 4. 中文不用斜体做分层

汉字没有斜体字形，阅读器是**几何拉斜**，一段白话斜下去既丑且伤读。

md 里可以写 `*白话*`，但**出成品时 `em` 必须改渲染**：不倾斜、降一档灰、左缩进、小一号。原文／译文、正文／注释的分层，靠灰度和缩进，不靠倾斜。

### 5. 危险内容照译，另附说明

古书里的毒方、药方、房中术照译不改（这是底本，不是建议）。**另起一行说清风险**，不混进译文。

## 五、出电子书（pandoc）

```bash
pandoc 译文/第*.md -o 书名.epub \
  --toc --toc-depth=1 --split-level=1 \
  --metadata title="…" --metadata author="…" --metadata lang=zh-CN \
  --css=style.css
```

两处中文特调，缺了就难看：

1. **目录要带回目**——把 `# 第N回` 和下一行的 `## 回目对句` 合成一个标题（在临时目录里做，别动原件），否则目录是一百条光秃秃的「第N回」。
2. **CSS 里 `em` 去斜体**（见上条 4）：`em { font-style: normal; color: #666; }` 再配缩进与小一号。

同一份 md 加 `-o x.docx` 出 Word。出 PDF 先确认本机有哪个引擎，别照抄网上的 xelatex 写法——没装 xelatex 时它只会报一句看不懂的错。

## 六、收工验收（三条，别跳）

第四节的「每回扫一眼」是过程闸，全书还要收口：

```bash
ls 译文/第*.md | wc -l                            # ① 应等于 ls 原文/*.txt | wc -l
grep -c "全本不删节" 译文/*.md | grep -v ":1$"     # ② 有输出＝有回的页脚闸句被改，逐件查
```

③ 按第四节条 3 抽查：本书哪几回有床笫段、哪几回有长文书（奏本／疏文／科仪／圣旨／题本／状纸），逐回对原文长度比一眼——**压缩过的一眼看得出来**。

## 七、不做什么

- **不为单本书起一件 skill**——这是方法，不是某本书专用。
- **不替作者说话**——古书里的判词、因果、报应照译；分析归分析（若被要），别混进正文。
- **不动既有的项目结构规矩**——目录、备份、留痕照你自己那套走。
